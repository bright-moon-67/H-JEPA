你报告的：

$$ \operatorname{MSE}_{\mathrm{head}}\approx0.0996 $$ $$ \operatorname{MSE}_{\mathrm{zero}}\approx0.0994 $$

对应：

$$ R^2_{\mathrm{response}} = 1-\frac{\operatorname{MSE}_{\mathrm{head}}} {\operatorname{MSE}_{\mathrm{zero}}} \approx-0.002 $$

所以现在还不能说网络学会了动作响应。不过，20 个梯度步骤、64 对训练样本不足以判断最终能力。

另一方面，你的固定探针实验已经说明：在真实 Push-T 仿真中，相同动作干预的物体效果会随初始状态变化。

例如，free 与 push 采样组的方块位移差异分别为 9.35 px 和 32.04 px。这为研究假设提供了物理证据，但还不是网络学习成功的证据。

接下来需要把这两个结果连接起来。

这里 P2 非常重要。

因为你的模型采用：

$$ R(z,A,B)=\phi(z,A)-\phi(z,B) $$

它本质上也是一种动作条件状态变化预测。原来的 H-JEPA World Model 可能已经隐式具备这种能力。

如果新增网络只是重复学习了原 Predictor 已经学到的内容，那么后续再做 Event Discovery，创新性和收益都会受到限制。

三、P1：先让 Action-Response Network 学到有效的非零响应
3.1 我建议首先修改评估指标，而不是立即改网络结构

目前 train_action_response.py 的 evaluate() 只输出：

{
    "mse": ...,
    "zero_effect_mse": ...
}

这不足以判断模型是否学会了动作的方向性、非零幅度和状态依赖性。

建议新增一个文件：

h_jepa/action_response_metrics.py

import torch
import torch.nn.functional as F


@torch.no_grad()
def compute_response_metrics(pred, target):
    """
    pred, target: [N, D]
    """
    assert pred.ndim == target.ndim == 2
    assert pred.shape == target.shape

    pred = pred.float()
    target = target.float()

    err = (pred - target).square().mean(dim=-1)
    energy = target.square().mean(dim=-1)

    mse = err.mean()
    zero_mse = energy.mean()

    r2 = 1.0 - mse / zero_mse.clamp_min(1e-12)

    target_norm = target.norm(dim=-1)
    pred_norm = pred.norm(dim=-1)

    # 仅在真实响应不接近零时统计方向
    valid = target_norm > 1e-3

    if valid.any():
        cosine = F.cosine_similarity(
            pred[valid], target[valid], dim=-1
        ).mean()

        magnitude_ratio = (
            pred_norm[valid].mean()
            / target_norm[valid].mean().clamp_min(1e-12)
        )
    else:
        cosine = torch.tensor(float("nan"))
        magnitude_ratio = torch.tensor(float("nan"))

    return {
        "mse": mse.item(),
        "zero_mse": zero_mse.item(),
        "r2": r2.item(),
        "cosine": cosine.item(),
        "magnitude_ratio": magnitude_ratio.item(),
        "target_rms": energy.mean().sqrt().item(),
        "pred_rms": pred.square().mean().sqrt().item(),
    }

这几个指标分别回答不同问题：

指标	研究意义
R²	是否优于始终预测零的模型
cosine	是否能够预测真实动作效应的方向
magnitude_ratio	是否低估或高估动作效应的大小
target_rms	数据集本身是否具有足够的动作响应信号
pred_rms	网络是否正在退化为近零响应

这里有一个非常重要的判据：

如果 R² 稍有改善，但 magnitude_ratio 很接近 0，说明网络可能只是学习了部分平均效应，并没有可靠预测实际动作的影响幅度。

不建议仅凭 MSE 下降就开始下一阶段。

3.2 增加一个很便宜的过拟合检查

在收集上千对数据之前，先验证网络能否拟合一个小数据集。

例如，从现有 64 对数据中取 16 对，反复训练 500–1000 个步骤。

这不是为了获得泛化性能，而是检验网络结构、数据、梯度是否存在问题。

可以新增一个单独的测试脚本，复用已有的 prepare_tensors()：

import torch
import torch.nn.functional as F

from action_response import ActionResponseNet, ResponseConfig


def tiny_overfit_check(tensors, device, steps=800):
    # tensors 来自已有 prepare_tensors()
    z = tensors["z0"][:16].to(device)
    a = tensors["a"][:16].to(device)
    b = tensors["b"][:16].to(device)
    y = tensors["target"][:16].to(device)

    net = ActionResponseNet(
        ResponseConfig(state_dim=z.shape[-1])
    ).to(device)

    opt = torch.optim.AdamW(net.parameters(), lr=1e-3)

    initial = None
    for i in range(steps):
        pred = net(z, a, b)
        loss = F.mse_loss(pred, y)

        if initial is None:
            initial = loss.item()

        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()

    final = F.mse_loss(net(z, a, b), y).item()
    print("initial:", initial)
    print("final:", final)
    print("zero_baseline:", y.square().mean().item())

    assert final < initial, "Network failed to fit tiny dataset"
    return net

不过，小样本过拟合成功仍然不能证明反事实效应可以泛化。

3.3 然后再扩充数据

我建议先收集约：

2,000–4,000 个训练 Anchor。
300–500 个验证 Anchor。
300–500 个独立测试 Anchor。

这是一个初步实验规模，不是必须达到的固定样本量。

相比单纯从 64 增加到 4,000，我更建议改变采样方式。

当前 Collector 对每个 Anchor 只生成一个动作对，且 B 是在 A 附近加入噪声得到的。

因此，动作效果的多样性可能受到限制。

建议改为：

每个物理 Anchor 生成多条动作分支，再随机组合成多个反事实动作对。

比如同一状态分别执行 4 条动作：

$$ A_0,A_1,A_2,A_3 $$

就能形成最多 6 个不同动作对。

这样更有利于区分：

预测是否真正依赖动作。
预测是否真正依赖当前状态。
网络是否只是记住了某种采样策略的平均动作效果。

重要的是：必须按 Anchor 划分 Train / Val / Test，而不是把同一个 Anchor 的不同动作对分到不同集合。

否则网络可能记住某个初始状态的响应，从而使验证结果偏高。

另一个实现重点是避免一次把几千对 224×224 的三张 RGB 图像全部堆进内存。建议把现有 NPZ Collector 改成按 Chunk 写出，或者使用 HDF5 存储；冻结 Encoder 的 Latent 可以预先计算并缓存。

3.4 一个很重要的采集优化：每个 Anchor 只重放 4 次，而不是每对动作都重放

你当前 collect_action_response_pusht.py 对每个动作对分别调用两次 run_branch()。如果一个 Anchor 需要 6 个动作对，就会重复模拟很多相同的分支。

建议改成：先生成 K 个候选动作，分别执行一次，然后组合结果。

核心代码如下，可作为改造现有 collect() 的辅助函数。

from itertools import combinations

import numpy as np


def make_action_branches(base_action, rng, horizon=5):
    """
    base_action: [2]
    返回 4 条 [5,2] 环境动作轨迹。
    """
    base = np.repeat(
        np.asarray(base_action, dtype=np.float32)[None],
        horizon,
        axis=0,
    )

    directions = [
        np.array([0.0, 0.0], dtype=np.float32),
        np.array([0.4, 0.0], dtype=np.float32),
        np.array([-0.4, 0.0], dtype=np.float32),
        np.array([0.0, 0.4], dtype=np.float32),
    ]

    branches = []

    for delta in directions:
        noise = rng.normal(
            0.0, 0.04, size=(horizon, 2)
        ).astype(np.float32)

        branch = np.clip(
            base + delta + noise, -1.0, 1.0
        ).astype(np.float32)

        branches.append(branch)

    return branches


def collect_pairs_at_anchor(
    env, anchor_seed, prefix, base_action, rng
):
    actions = make_action_branches(base_action, rng)

    # 每条真实动作分支只运行一次
    outcomes = [
        run_branch(env, anchor_seed, prefix, a)
        for a in actions
    ]

    # 验证所有分支起点一致
    for result in outcomes[1:]:
        np.testing.assert_allclose(
            result["start_state"],
            outcomes[0]["start_state"],
            atol=1e-5,
            rtol=0,
        )
        assert np.array_equal(
            result["start_rgb"],
            outcomes[0]["start_rgb"],
        )

    rows = []

    for i, j in combinations(range(len(actions)), 2):
        A = outcomes[i]
        B = outcomes[j]

        rows.append({
            "rgb0": A["start_rgb"],
            "rgb_a": A["end_rgb"],
            "rgb_b": B["end_rgb"],
            "acts_a": actions[i],
            "acts_b": actions[j],
            "state0": A["start_state"],
            "state_a": A["end_state"],
            "state_b": B["end_state"],
            "contacts_a": A["contacts"],
            "contacts_b": B["contacts"],
            "anchor_seed": anchor_seed,
        })

    return rows

这四个分支将产生 6 个动作对。将来还可以增加反向动作、较大幅度扰动和不同持续时间的探针。

请提醒 Agent：6 个动作对不等于 6 个独立的初始状态。 它们共享同一个 Anchor，统计有效样本量和训练/验证划分都需要考虑这一点。

此外，当前环境的 PushT 类默认 with_target=True，但你新 Collector 显式使用 with_target=False。这意味着采集图像可能与正式规划时的图像分布不一致。

因此，在扩大数据量之前，应当先比较原训练集图像、正式评估图像和反事实采集图像的渲染设置，确认模型编码输入分布是否一致。不要未经验证就把 Collector 全面切换为另一种渲染方式。

四、P2：必须补上原始 World Model 的反事实差分基线

这一步我认为非常关键，而且可以在现有数据集上立即做。

原始 Level-1 World Model 同样可以接受动作 A、B，分别预测未来 Latent：

$$ \hat z_A=F^{(1)}(z_0,A) $$ $$ \hat z_B=F^{(1)}(z_0,B) $$

然后构造：

$$ \boxed{ \hat r_{\mathrm{WM}}=\hat z_A-\hat z_B } $$

与新增 Action-Response Network 比较：

$$ \hat r_{\mathrm{ARN}}=R_\psi(z_0,A,B) $$

这相当于问：

专门学习反事实差异，是否比直接使用已有 World Model 的动作预测更准确？

4.1 结合实际源码的一个重要细节

你原始训练配置中的 history_size=3，但 JEPA.rollout() 默认使用 history_size=1 进行规划展开。

所以这里存在两种合理的对照：

Planner-mode Baseline：只使用当前 \(z_0\) 和一个 5 步动作块，符合规划时第一步预测的上下文长度。现有 NPZ 就可以测试。
Training-context Baseline：使用连续 3 个历史 Latent State 和相应动作，需要额外保存历史图像与动作块。

我建议先实现第一种，因为它最直接对应规划器实际使用的模型。

from pathlib import Path

import torch

from data import (
    NORMALIZER_ARTIFACT_FILENAME,
    load_normalizer_artifact,
)


def get_action_stats(model, ckpt_path, device):
    artifact = getattr(
        model, "normalizer_artifact", None
    )

    if artifact is None:
        normalizer_path = (
            Path(ckpt_path).parent
            / NORMALIZER_ARTIFACT_FILENAME
        )

        artifact = load_normalizer_artifact(
            normalizer_path
        )

    stats = artifact["stats"]["action"]

    mean = torch.as_tensor(
        stats["mean"],
        dtype=torch.float32,
        device=device,
    ).reshape(-1)

    std = torch.as_tensor(
        stats["std"],
        dtype=torch.float32,
        device=device,
    ).reshape(-1)

    assert mean.numel() == 2
    assert std.numel() == 2
    assert (std > 0).all()

    return mean, std


@torch.no_grad()
def predict_level1_once(
    level1, z0, actions, mean, std
):
    """
    z0:     [B,192]
    actions:[B,5,2]  原始环境动作

    输出：预测 5 个环境步后的 Level-1 latent。
    """
    B = z0.shape[0]

    assert z0.shape == (B, 192)
    assert actions.shape == (B, 5, 2)

    # 使用原训练数据的 Action Normalizer
    normalized = (
        actions - mean.view(1, 1, 2)
    ) / std.view(1, 1, 2)

    # Level-1 的动作块是 5*2 = 10 维
    action_block = normalized.reshape(B, 1, 10)

    action_latent = level1.action_encoder(
        action_block
    )
    action_embed = level1.action_embed(
        action_latent
    )

    # 与规划时第一步预测保持一致
    pred = level1.predict(
        z0.unsqueeze(1),
        action_embed,
    )

    return pred[:, -1, :]


@torch.no_grad()
def predict_wm_response(
    model, z0, actions_a, actions_b,
    ckpt_path,
):
    level1 = model.get_level(1)
    device = z0.device

    mean, std = get_action_stats(
        model, ckpt_path, device
    )

    za = predict_level1_once(
        level1, z0, actions_a, mean, std
    )
    zb = predict_level1_once(
        level1, z0, actions_b, mean, std
    )

    return za - zb

五、P3：建立最小可运行的动力学事件检测器

只有在 P1、P2 证明 Response Network 学到了有意义的动作效应后，我才建议开展这一步。

这里仍然不修改 Level 2，不改变原 H-JEPA 的时间抽象结构。

我们只训练或构建一个独立的事件检测器。

5.1 输入不是单次动作效应，而是一组固定动作探针

对于每个状态 \(z_t\)，定义 K 组固定动作：

$$ A_1,A_2,\ldots,A_K $$

选择统一的参考动作：

$$ A_{\mathrm{ref}} $$

得到：

$$ \boxed{ \mathcal R_t= \begin{bmatrix} R(z_t,A_1,A_{\mathrm{ref}})\\ \vdots\\ R(z_t,A_K,A_{\mathrm{ref}}) \end{bmatrix} } $$

维度为：

$$ \mathcal R_t\in\mathbb R^{K\times192} $$

它描述的是在当前状态下，不同动作扰动可能产生的未来差异。

然后比较连续两个状态的动作响应结构：

$$ \boxed{ b_t= \sqrt{ \frac{1}{KD} \|\mathcal R_t-\mathcal R_{t-1}\|_F^2 } } $$

如果 \(b_t\) 明显增大，说明动作响应结构变化较大。

但这只是候选事件分数，不是已经证明的动力学机制切换概率。

它可能受到普通状态变化或 Encoder 表征变化影响。必须与原始 Latent Change 进行对照。

5.2 可直接新增的代码

建议文件：

h_jepa/causal_event.py

import torch


@torch.no_grad()
def action_response_signature(
    response_net,
    states,
    probe_actions,
    reference_action,
):
    """
    states:           [T,192]
    probe_actions:    [K,5,2]
    reference_action: [5,2]

    returns:          [T,K,192]
    """
    T, D = states.shape
    K = probe_actions.shape[0]

    assert probe_actions.shape[1:] == (5, 2)
    assert reference_action.shape == (5, 2)

    # 每个状态使用相同的动作探针
    z = states[:, None, :].expand(
        T, K, D
    ).reshape(T * K, D)

    actions = probe_actions[None].expand(
        T, K, 5, 2
    ).reshape(T * K, 5, 2)

    reference = reference_action[
        None, None
    ].expand(
        T, K, 5, 2
    ).reshape(T * K, 5, 2)

    signature = response_net(
        z, actions, reference
    )

    return signature.reshape(T, K, D)


@torch.no_grad()
def causal_event_score(signatures):
    """
    signatures: [T,K,D]
    return:     [T-1]
    """
    delta = (
        signatures[1:]
        - signatures[:-1]
    )

    return delta.square().mean(
        dim=(1, 2)
    ).sqrt()


@torch.no_grad()
def latent_change_score(states):
    """
    states: [T,D]
    用作对照：普通 latent 状态变化。
    """
    delta = states[1:] - states[:-1]

    return delta.square().mean(
        dim=-1
    ).sqrt()

这个实现具有两个优点：

第一，完全不需要任务专属状态。 同样的代码以后可以用于 Cube 或 AntMaze。

第二，不会改变原始 H-JEPA 的训练和规划。 可以先独立验证事件分数是否有意义。

5.3 如何快速验证事件检测？

建议从现有 Push-T 轨迹中提取连续图像，每 5 个环境步计算一次：

$$ z_0,z_5,z_{10},z_{15},\ldots $$

对应：

$$ b_5,b_{10},b_{15},\ldots $$

然后使用仿真器记录的接触情况、物体运动变化等量进行事后比较。

需要至少比较三种信号：

事件检测信号	用途
原始 Latent Change	普通状态变化的参照
Action-Response Signature Change	我们提出的信号
随机/固定间隔检测	排除纯粹随机或周期性触发

我不建议一开始训练很复杂的 Boundary Network。

先检查最基本的：

动作响应变化是否比普通 Latent Change 更能识别物理交互状态的转变？

如果不能，说明目前还没有足够依据引入 Event Abstraction。

如果可以，再考虑学习一个从连续动作响应中预测事件边界的网络。

六、P4：如何在保留原始 Checkpoint 的情况下，让这两项研究真正改善 H-JEPA？

这一部分是对你之前提出的要求的直接回答：

不重新设计 Level 2，不改变层次数量，也不从头训练 World Model，只对原始 Level-1 Predictor 进行小规模微调。

但我建议把它作为 P1–P3 达标后的实验，而不是立即执行。

6.1 微调哪个模块？

从仓库源码可以确认，Push-T 的 Level-1 Predictor 是一个 ProjectedPredictor，内部包含原始自回归预测器和输出 Projector。

第一版可以只训练：

model.get_level(1).predictor.projector

其余保持冻结，包括：

模块	第一版微调策略
Level-1 Encoder	冻结
Level-1 Predictor 主干	冻结
Level-1 Predictor Projector	微调
Level-1 Action Embedding	冻结
Level-2 Encoder	冻结
Level-2 Predictor	冻结
Action-Response Network	作为已训练的辅助模型，冻结

为什么不先微调 Encoder？

因为 Level 2 已经在原始 Level-1 Latent Space 上训练完毕。

如果大幅修改 Level-1 Encoder，原来 Level-2 Encoder 和 Predictor 对 Latent State 的理解也可能失效。

而只修改 Level-1 Predictor 的输出映射，至少可以保持真实观测的编码空间不变。

当然，这并不能保证性能一定提高。它只是一个更容易控制变量、保留原 Checkpoint 兼容性的起点。

6.2 设计一个由动作响应和事件信号共同指导的损失

这里仍然使用原始 H-JEPA 的 World Model，不另外构建新的高层动力学网络。

令原始模型对两组动作的预测为：

$$ \hat z_A,\hat z_B $$

真实反事实标签为：

$$ z_A=E^{(1)}(o_A),\qquad z_B=E^{(1)}(o_B) $$

定义：

第一项：原始终点预测损失

$$ \mathcal L_{\mathrm{abs}} = \|\hat z_A-z_A\|^2 + \|\hat z_B-z_B\|^2 $$

第二项：动作效应一致性损失

$$ \boxed{ \mathcal L_{\mathrm{effect}} = \|(\hat z_A-\hat z_B)-(z_A-z_B)\|^2 } $$

这个损失直接要求原始 Predictor 更准确地反映改变动作造成的结果差异。

第三项：事件权重

令前面事件检测器计算的分数为 \(b_t\)，通过训练集统计量归一化为：

$$ \bar b_t\in[0,1] $$

然后：

$$ w_t=1+\lambda_b\bar b_t $$

得到：

$$ \boxed{ \mathcal L_{\mathrm{finetune}} = \mathbb E_t\left[ w_t \left( \mathcal L_{\mathrm{abs}} + \lambda_r\mathcal L_{\mathrm{effect}} \right) \right] + \lambda_k\mathcal L_{\mathrm{keep}} } $$

其中：

$$ \mathcal L_{\mathrm{keep}} = \|\hat z_A-\hat z_A^{\mathrm{original}}\|^2 + \|\hat z_B-\hat z_B^{\mathrm{original}}\|^2 $$

用于约束微调后的输出不要无必要地偏离原模型。

这样，两个前期模块都真正参与原世界模型的改进：

Action-Response Learning 告诉 Predictor 哪些动作差异应该产生不同结果。
Event Discovery 让 Predictor 更关注动作作用关系发生明显变化的训练片段。

它仍然属于原始 Level-1 Dynamics 的微调，而不是构造一个新世界模型。

这里要明确：事件分数的有效性尚未得到验证。在事件信号通过测试前，应先将 \(w_t=1\)，单独验证反事实效应损失的收益。

6.3 代码实现示例

建议单独新建：

h_jepa/scripts/finetune_effect_level1.py

不要直接修改原 main_hjepa.py。

核心代码可以采用：

import torch
import torch.nn.functional as F


def select_trainable_parameters(model):
    # 首先冻结整个 H-JEPA
    model.eval()

    for p in model.parameters():
        p.requires_grad_(False)

    # 仅微调 Level-1 Predictor 的输出 Projector
    projector = model.get_level(1).predictor.projector

    for p in projector.parameters():
        p.requires_grad_(True)

    params = list(projector.parameters())

    assert params, "Predictor projector has no parameters"

    return params


def predict_level1_differentiable(
    level1, z0, raw_actions, action_mean, action_std
):
    """
    注意：不能加 @torch.no_grad()！
    z0:          [B,192]  冻结编码结果
    raw_actions: [B,5,2]
    """
    B = z0.shape[0]

    normalized = (
        raw_actions - action_mean.view(1, 1, 2)
    ) / action_std.view(1, 1, 2)

    action_block = normalized.reshape(B, 1, 10)

    act = level1.action_encoder(action_block)
    act_emb = level1.action_embed(act)

    # 与原规划器第一步的预测接口一致
    pred = level1.predict(
        z0.unsqueeze(1),
        act_emb,
    )

    return pred[:, -1, :]


def compute_finetune_loss(
    model,
    batch,
    action_mean,
    action_std,
    lambda_effect=0.5,
    event_weight=None,
    baseline_pred_a=None,
    baseline_pred_b=None,
    lambda_keep=0.1,
):
    """
    batch:
      z0, z_a, z_b: [B,192]
      a, b:         [B,5,2]

    z_a/z_b 必须来自冻结的原始 Encoder。
    """
    level1 = model.get_level(1)

    z0 = batch["z0"].detach()
    z_a = batch["z_a"].detach()
    z_b = batch["z_b"].detach()

    pred_a = predict_level1_differentiable(
        level1, z0, batch["a"],
        action_mean, action_std,
    )

    pred_b = predict_level1_differentiable(
        level1, z0, batch["b"],
        action_mean, action_std,
    )

    # 单样本绝对预测误差
    abs_error = (
        (pred_a - z_a).square().mean(dim=-1)
        + (pred_b - z_b).square().mean(dim=-1)
    )

    # 单样本动作效应预测误差
    true_effect = z_a - z_b
    pred_effect = pred_a - pred_b

    effect_error = (
        (pred_effect - true_effect)
        .square()
        .mean(dim=-1)
    )

    sample_loss = (
        abs_error + lambda_effect * effect_error
    )

    if event_weight is not None:
        assert event_weight.shape == sample_loss.shape
        sample_loss = (
            sample_loss * event_weight.detach()
        )

    loss = sample_loss.mean()

    if baseline_pred_a is not None:
        assert baseline_pred_b is not None

        keep_loss = (
            F.mse_loss(
                pred_a, baseline_pred_a.detach()
            )
            + F.mse_loss(
                pred_b, baseline_pred_b.detach()
            )
        )

        loss = loss + lambda_keep * keep_loss

    return loss

这里要提醒 Agent 三个关键事项。

第一，微调预测函数不能继续使用 P2 中的 @torch.no_grad()，否则梯度无法传到 Predictor Projector。

第二，z_a、z_b 必须来自冻结的原始 Encoder。当前 prepare_tensors() 只返回 target=z_a-z_b，因此需要在微调数据准备函数中额外保留这两个张量，不能只使用差异目标。

第三，如果使用 Event Weight，现有数据集只有当前 Anchor，没有连续历史的完整事件分数。因此 Collector 需要进一步保存至少相邻采样时刻的观测，或者在连续轨迹上预先计算并按 Anchor ID 关联事件分数。不能用 mode=="push" 或 n_contacts>0 直接冒充学习得到的事件分数。

这样才不会把原本希望实现的任务无关机制变成 Push-T 专用监督。
