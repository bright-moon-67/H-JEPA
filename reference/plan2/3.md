### 2. 你的 Contact 子集还不能作为 Event Boundary 标签

`compare_response_methods.py` 目前把一个动作对的两条分支的接触计数相加，只要至少一条分支发生过接触，就归入 `contact` 子集。

![](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub

这对于评价“包含接触的动作响应预测”是合理的。

但它并不能区分：

* 接触刚刚发生。

* 接触正在持续。

* 接触已经结束。

而我们下一阶段要研究的恰恰是动力学作用机制何时发生变化。

因此，P3 必须额外记录连续执行过程中的接触时刻，而不能直接把现有 H5 中的 `contacts > 0` 当作事件边界。

### 3. 当前动作采样分布比较有限

你的多分支 Collector 通过 `steer_action()` 生成引导动作，再添加几个固定方向扰动。当前 4 分支主要使用零扰动、正负 X 扰动和正 Y 扰动。

![](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub

这能高效产生较多物理交互，但也意味着测试集的动作仍然来自相同的采样策略。

因此，当前 R² 更准确的解释是：

模型能够泛化到新的 Anchor，但还没有证明能够泛化到不同的动作采样分布。

建议新增一个独立测试集，保留相同的真实仿真器和冻结 Encoder，但改变扰动方向、幅度和动作序列结构。

不需要重新训练，先用现有 ARN 与冻结 WM 测试。

如果 ARN 在新动作分布上明显退化，而原 WM 保持稳定，说明目前的专项网络更容易学习特定采样策略。

### 4. 反事实数据最好保存完整的 Roll-in Actions

现在 H5 保存了 `anchor_seed` 和 `prefix_len`，但没有保存完整的历史动作前缀。

![](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub+1

由于前缀由随机数发生器和采样算法共同决定，今后只要调整生成逻辑，就可能无法精确恢复旧 Anchor。

这在 P3 尤其重要，因为你将需要沿着同一条轨迹计算连续时间的动作响应。

我建议新增 `prefix_actions`，采用 Padding + `prefix_len` 或者 HDF5 的变长数组进行保存。

这是一个小改动，但会明显改善事件实验的可复现性。

```
import numpy as np


def paired_anchor_bootstrap(
    pred_wm,
    pred_arn,
    target,
    anchor_idx,
    n_boot=2000,
    seed=42,
):
    """
    pred_wm, pred_arn, target: [N_pairs, D]
    anchor_idx: [N_pairs]

    正值意味着 ARN 比 WM 的 MSE 更低。
    """
    wm_error = np.mean(
        (pred_wm - target) ** 2, axis=1
    )
    arn_error = np.mean(
        (pred_arn - target) ** 2, axis=1
    )

    pair_improvement = wm_error - arn_error

    anchors, inverse = np.unique(
        anchor_idx, return_inverse=True
    )

    count = np.bincount(inverse)
    anchor_improvement = (
        np.bincount(
            inverse,
            weights=pair_improvement
        ) / count
    )

    rng = np.random.default_rng(seed)

    sampled = rng.integers(
        0,
        len(anchors),
        size=(n_boot, len(anchors)),
    )

    bootstrap_means = (
        anchor_improvement[sampled]
        .mean(axis=1)
    )

    ci_low, ci_high = np.quantile(
        bootstrap_means, [0.025, 0.975]
    )

    return {
        "mean_mse_gain": anchor_improvement.mean(),
        "ci95": (ci_low, ci_high),
        "n_anchors": len(anchors),
    }
```

判断方式：

如果 95% 置信区间下界大于零，说明在当前测试分布和世界模型下，ARN 的 MSE 改善有更充分的统计支持。

如果区间跨越零，就不应该声称 ARN 优于原始 Predictor。

此外，可以对 `contact` 和 `no-contact` 分组分别计算，但需要明确每组的样本数量。

## 最终建议
