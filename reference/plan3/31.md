# RAGC-HJEPA：严格对齐仓库的实现方案

我建议把这次工作分成三个阶段：先证明真实动作修正存在成功率收益空间，再训练 RAGC 修正网络，最后无侵入地接入原始分层规划器。

最重要的约束是：不再把 Latent R²、动作排序相关性或事件检测分数作为最终目标。是否继续，始终由完整 Push-T Episode 的成功率决定。

## 1. 简单思路

原始 H-JEPA 使用世界模型生成可微代价，通过梯度下降找到动作：

A∗=arg⁡min⁡AJHJEPA(A)A^*=\arg\min_A J_{\mathrm{HJEPA}}(A)A∗=argAminJHJEPA(A)

RAGC 则从真实仿真经验中学习一个任务收益函数：

Qϕ(zt,g,A)Q_\phi(z_t,g,A)Qϕ(zt,g,A)

这里约定 QϕQ_\phiQϕ 越小，动作越好。

为了避免破坏已有 Checkpoint，我们不替换原始规划器，而是在它完成优化之后，对动作进行小幅二次修正：

A′=arg⁡min⁡∥A−A∗∥≤δ\(JHJEPA(A)−JHJEPA(A∗)sJ+λ(Qϕ(A)−Qϕ(A∗))+μ∥A−A∗∥2\)\boxed{ A'=\arg\min_{\|A-A^*\|\leq\delta} \left\( \\frac{J\_{\\mathrm{HJEPA}}(A)-J\_{\\mathrm{HJEPA}}(A^\*)}{s\_J} +\\lambda\\bigl(Q\_\\phi(A)-Q\_\\phi(A^\*)\\bigr) +\\mu\\|A-A^\*\\|^2 \\right\) }A′=arg∥A−A∗∥≤δmin\(sJ​JHJEPA​(A)−JHJEPA​(A∗)​+λ(Qϕ​(A)−Qϕ​(A∗))+μ∥A−A∗∥2\)

其中 sJs_JsJ 是原始规划代价的尺度因子。

这个设计有三个优点：

* 原始 Level 1、Level 2、Encoder、Predictor 和高层 Subgoal 全部保留。

* 使用你已有的反事实仿真经验训练动作修正信号。

* 即使网络尚不可靠，也能通过信赖域和原代价保护机制回退到原始动作。

原始 H-JEPA Level 2

优化高层动作，生成 Subgoal

原始 H-JEPA Level 1

GradientSolver 得到 A*

RAGC · Realized-Advantage Correction

根据真实执行结果训练的梯度信号，微调 A*

执行修正动作，按原始时间表重规划

不修改原始 WorldModelPolicy 的闭环周期

这仍然是一个待验证的方法假设。不能保证仅靠局部动作修正就能改善 Push-T 成功率，因此必须先做上界实验。

这是我最建议你严格要求 Agent 先完成的部分。

A∗∈R2×10A^*\in\mathbb R^{2\times10}A∗∈R2×10

A+=A∗+ϵuA^+=A^*+\epsilon uA+=A∗+ϵu

A−=A∗−ϵuA^-=A^*-\epsilon uA−=A∗−ϵu

其中 uuu 是单位扰动方向。

对应代码位于 `ragc_oracle.py`：

Python

运行

```
def antithetic_candidates(a_star, eps, directions, rng):
    base = np.asarray(a_star, np.float32)
    out = [base.copy()]

    for _ in range(directions):
        u = rng.normal(size=base.shape).astype(np.float32)
        u /= max(float(np.linalg.norm(u)), 1e-12)

        out.extend([
            base + eps * u,
            base - eps * u,
        ])

    return out
```

### 3.3 第三步：用完整任务结果产生训练标签

epos=∥s0:4−g0:4∥2e_{\mathrm{pos}} = \|s_{0:4}-g_{0:4}\|_2epos=∥s0:4−g0:4∥2

这里的 Success 必须是整段真实执行过程中是否满足环境成功条件，而不是简单看最终 Latent Distance。

## 3.4 第四步：训练 Realized-Advantage Head

当上界实验表明存在可被局部动作扰动救回的任务时，再开始训练。

输入：

Qϕ(zt,g,A)Q_\phi(z_t,g,A)Qϕ(zt,g,A)

其中：

* ztz_tzt：原始 H-JEPA Level-1 当前状态。

* ggg：原 Solver 当前的目标，可能来自 Level 2。

* AAA：标准化的 Level-1 动作序列。

* 额外标志：目标是否位于高层 Latent Space。

### 需要注意 Level 1 / Level 2 表征的区别

虽然 Push-T 两层 Latent 都是 192 维，但它们并不是同一个表示空间。

因此，新网络采用拼接输入，而不是计算：

zt−gz_t-gzt−g

完整代码位于 `ragc.py`，核心输入结构为：

Python

运行

```
class RealizedAdvantageHead(nn.Module):
    def __init__(self, cfg):
        super().__init__()

        input_dim = (
            cfg.state_dim
            + cfg.goal_dim
            + cfg.max_horizon * cfg.token_dim
            + 2
        )

        self.net = nn.Sequential(
            nn.LayerNorm(input_dim),
            nn.Linear(input_dim, cfg.hidden_dim),
            nn.SiLU(),
            nn.Linear(cfg.hidden_dim, cfg.hidden_dim),
            nn.SiLU(),
            nn.Linear(cfg.hidden_dim, 1),
        )

    def forward(self, z0, goal, actions, goal_is_upper):
        # 验证维度、对短 Horizon 补零
        # 构建 horizon 长度与 goal-space 标志
        # 拼接，而不是跨层 latent 相减

        x = build_features(
            z0,
            goal,
            actions,
            goal_is_upper,
        )

        return self.net(x).squeeze(-1)
```

上面为了突出结构省略了 `build_features` 的内部实现；代码包中的 `RealizedAdvantageHead.forward()` 是完整、自包含的版本，不需要额外定义这个函数。

### 训练损失

对于相同起点的正负扰动：

A+=A∗+ϵuA^+=A^*+\epsilon uA+=A∗+ϵu

A−=A∗−ϵuA^-=A^*-\epsilon uA−=A∗−ϵu

真实有限差分为：

dreal=C(A+)−C(A−)2ϵd_{\mathrm{real}} = \frac{C(A^+)-C(A^-)}{2\epsilon}dreal=2ϵC(A+)−C(A−)

预测有限差分为：

dϕ=Qϕ(A+)−Qϕ(A−)2ϵd_\phi = \frac{Q_\phi(A^+)-Q_\phi(A^-)}{2\epsilon}dϕ=2ϵQϕ(A+)−Qϕ(A−)

主要训练目标：

LRAGC=λvLvalue+λdLdifference+λgLgradient+λrLranking\boxed{ \mathcal L_{\mathrm{RAGC}} = \lambda_v\mathcal L_{\mathrm{value}} + \lambda_d\mathcal L_{\mathrm{difference}} + \lambda_g\mathcal L_{\mathrm{gradient}} + \lambda_r\mathcal L_{\mathrm{ranking}} }LRAGC=λvLvalue+λdLdifference+λgLgradient+λrLranking

其中最有辨识度的是：

Lgradient=Huber⁡(dϕ,dreal)\mathcal L_{\mathrm{gradient}} = \operatorname{Huber}(d_\phi,d_{\mathrm{real}})Lgradient=Huber(dϕ,dreal)

代码包中的 `paired_realized_advantage_loss()` 已包含这些分量。

请提醒 Agent：

正负候选必须严格关于原始动作对称，并且使用实际扰动幅度 ϵ\epsilonϵ。

如果执行时发生 Action Clipping，那么正负扰动可能不再对称，此时不能直接使用原来的中心差分公式。

### 4.2 修正器如何控制动作变化？

完整实现中，`RAGCRefiner` 会执行：

1. 保存原始动作 A∗A^*A∗。

2. 计算原始模型代价与 RAGC 预测代价。

3. 进行少量梯度修正。

4. 将动作限制在原始动作附近。

5. 检查新的动作是否使 RAGC 代价下降。

6. 检查原始模型代价是否恶化过多。

7. 不满足条件则退回原始动作。

关键逻辑是：

Python

运行

```
accept = (
    predicted_gain >= min_advantage_improvement
) & (
    new_original_cost
    <= old_original_cost + allowed_regression
)

final_actions = torch.where(
    accept[:, None, None],
    corrected_actions,
    original_actions,
)
```

这里的保护只能避免模型自身预测出现明显恶化，不能保证真实任务一定更好。因此最终仍需要闭环实验。

```
    _is_hierarchical_solver(cfg)
    and ragc_cfg is not None
    and bool(ragc_cfg.get("enabled", False))
):
    from dataclasses import replace
    from pathlib import Path

    from ragc import (
        RAGCConfig,
        RealizedAdvantageHead,
        RAGCRefiner,
    )
    from action_response_wm import get_action_stats

    ckpt_path = Path(str(ragc_cfg["head_checkpoint"]))

    payload = torch.load(
        ckpt_path,
        map_location="cpu",
        weights_only=True,
    )

    if payload.get("supervision") != "baseline_continuation":
        raise RuntimeError(
            "RAGC requires real continuation labels"
        )

    base_cfg = RAGCConfig(
        **payload["ragc_config"]
    )

    refine_cfg = replace(
        base_cfg,
        **dict(ragc_cfg.get("refine", {})),
    )

    head = RealizedAdvantageHead(refine_cfg)

    head.load_state_dict(
        payload["head_state_dict"]
    )

    device = next(model.parameters()).device
    head = head.to(device).eval()

    mean, std = get_action_stats(
        model, cfg.policy, device
    )

    solver.set_ragc_refiner(
        RAGCRefiner(
            head,
            refine_cfg,
            mean,
            std,
        )
    )
```

# 六、必须提醒 AI Agent 的错误

以下几项我认为应该作为不可跳过的代码审查条件。

### 错误 1：直接沿用旧 `action_ranking_test.py` 的 Solver 配置

旧脚本曾在生成动作之前将：

Python

运行

```
action_cost_weight = 0.0
```

这会使原始 Solver 不再是正式评估的 Baseline。

RAGC 必须保留 Push-T 原来的 `action_cost_weight=0.2`。

而且不能对第 20、40、60 步都传入 `steps_taken=0`，应传入真实经过的环境步数。

### 错误 2：直接使用中途七维状态作为完整反事实初始状态

它无法恢复物体隐藏速度与接触历史。

必须从相同的 Episode 初始条件，重放完全相同的动作前缀。

### 错误 3：拿随机反事实动作训练 RAGC，却用在原始优化动作附近

这是上一轮 ARN 遇到 OOD 问题的一个潜在来源。

RAGC 训练样本应围绕原始 H-JEPA 实际优化得到的动作采集。

这样训练分布更接近部署时需要修正的动作分布。

### 错误 4：把原高层 Goal 当成 Level-1 Goal

RAGC 使用的是原 Solver 实际交给 Level 1 的 `goal_embed_0`。

不同规划时刻，这个目标可能是 Level-2 Subgoal，也可能在上层规划被跳过后变成实际 Goal。

不能假设它始终属于同一个 Latent Space。

### 错误 5：只让 RAGC 预测短期物理距离

短期距离减小并不必然提高最终成功率。

第一版训练标签最好来自完整 Baseline Continuation，避免重新陷入“中间指标提高而成功率不变”的问题。

### 错误 6：没有处理动作合法性和信赖域

原始 Solver 的动作是标准化 Token。

必须使用训练时的 Action Mean/Std，检查转换到环境动作后的范围，并明确处理原动作本身超出范围的情况。

参考实现对这类原始动作采取保守策略，不将裁剪导致的变化误认为 RAGC 收益。

### 错误 7：修正后仍返回原动作对应的预测结果

原 `GradientSolver` 返回的 `predictions` 对应修正前的动作。

因此，修正后不能将旧预测作为新动作的预测结果继续使用。

当前 `HierarchicalSolver.solve()` 只向 Policy 返回 `actions`，所以参考方案保持这一返回语义，不额外传递过期的预测。

### 错误 8：只统计成功任务的提升，不统计退化任务

最终必须记录：

Ngain=#(Baseline失败，RAGC成功)N_{\mathrm{gain}} = \#(\text{Baseline失败，RAGC成功})Ngain=#(Baseline失败，RAGC成功)

Nloss=#(Baseline成功，RAGC失败)N_{\mathrm{loss}} = \#(\text{Baseline成功，RAGC失败})Nloss=#(Baseline成功，RAGC失败)

实际净收益为：

ΔN=Ngain−Nloss\Delta N=N_{\mathrm{gain}}-N_{\mathrm{loss}}ΔN=Ngain−Nloss

不能只展示“成功救回了哪些任务”。

# 八、我的最终实施建议

这次请严格区分两件事：

RAGC 的机制创新： 利用真实同状态动作干预得到的任务收益，训练可微的局部动作修正信号。

最终目标： 在冻结原始 H-JEPA 的条件下，提高真实闭环 Push-T 成功率。

前者只是方法，后者才是成功标准。

我建议你实际交给 AI Agent 时，不要让它直接执行所有阶段，而是：

先完成阶段 0 的反事实收益上界实验与原策略一致性检查。

如果它能证明原始失败任务中确实存在可以通过局部动作修正获得成功的案例，再使用这套代码训练 RAGC，并开展闭环对照。

这样既保留了一个有研究潜力的创新点，也能避免再次投入大量实验后才发现研究指标与成功率无关。

最关键的验收问题只有一个：RAGC 是否让原始 22/50 的 Push-T L2 Baseline，在相同任务、相同 Checkpoint 和可比较计算预算下，获得更多的净成功任务？

只要这个问题没有得到肯定结果，就不应该把 RAGC 视为已经有效的改进。
