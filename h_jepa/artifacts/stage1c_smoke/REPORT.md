# Stage 1C — 小样本采集 + 训练接线 结果报告

Commit 对应代码：`ragc_collect.py`（共用采集器）、`collect_ragc_stage1.py`（采集入口）、
`ragc_stage1_report.py`（标签统计）、`eval_ragc_head.py`（Head 分组评估）。

## 1. 采集配置

| 项 | 值 |
|---|---|
| 数据源 | `pusht_expert_train.h5`（18,685 episodes / 2,336,736 frames） |
| 任务划分 | train = ep0040–0045，val = ep0046–0049（**按 episode ID，不交叉**） |
| 窗口 | goal_offset = 75，起点按 episode 偏移（记录在 `task_uid`） |
| 每个 Anchor | A* + 4 个对偶扰动（ε=0.3，2 方向） |
| 后续执行 | 原始冻结 H-JEPA，跑到 eval_budget=90 |
| Anchor 数 | 10（每任务 1 个，首次规划时刻） |
| 计算量 | 约 10 × 54 ≈ 540 次 solver 调用（GPU 约 55 分钟，单卡 3090） |

## 2. 数据有效性

- Anchor 总数 **10**，有效 **10**，无效 **0**
- 严格重放门禁（A* 分支：锚点指纹 / RGB / 剩余动作序列 / 成功性）全部通过
- train/val **episode 无交叉**（`{"source_episode_uid"}` 断言）
- 真实动作范围：`max|a| = 0.785`，越界比例 **0.0000**（无 clipping 混淆）
- 逐 Anchor JSONL + fsync，采集中断不丢数据

## 4. 两种 ΔC 必须分开看

**(a) 候选相对 A\*（工程观测，非训练目标）**
`dC_i = C(A_i) − C(A*)`：n=40，mean=+0.054，median=−0.018，范围 [−1.485, +1.746]，**40/40 非零**
- 基线成功 Anchor：mean=+0.527（扰动多为负收益）
- 基线失败 Anchor：mean=−0.419（扰动多为正收益）

**(b) 正负动作对差（真正的监督目标）**
`dC = C(A+) − C(A−)`：n=20，mean=+0.283，median=+0.020，范围 [−1.104, +1.828]
- 非零：**20/20**
- `|dC| > 0.5`：**10/20**

> 结论：大幅值样本充足，但"任务结果变化大" ≠ "每个方向都有可用梯度"。20 对里只有 10 对存在成功性翻转。

### 4.1 失败态的"连续代价改善"与"真正救回"必须分开（20 个失败态候选）

| 类别 | 数量 | 说明 |
|---|---|---|
| **真正救回**（成功性翻转） | **4 / 20** | 只有这些能计入 $\Delta N$ |
| 仅连续代价改善、仍失败 | **13 / 20** | mean −0.344、median −0.371、min −0.652 |
| 代价变差 | 3 / 20 | |

> 也就是说：失败态里 65% 的候选"看起来更好"（距离代价下降 0.34），但**没有一个达到成功条件**。
> 如果只看连续代价，会严重高估可用性。

### 4.2 成功态的破坏与保持（20 个成功态候选）

| 类别 | 数量 |
|---|---|
| **破坏 Episode**（成功 → 失败） | **8 / 20 (40%)** |
| 仍成功、代价持平/更低 | 6 / 20 |
| 仍成功、代价更高但未翻转 | 6 / 20 |

> 收益/风险极不对称：救回 4 个，破坏 8 个（候选级 $\Delta N = -4$）。这正是 Head 必须学会"不该动就不动"的原因。


## 5. 划分构成（关键偏差）

| split | 对数 | 来自原成功 Anchor | 来自原失败 Anchor | 成功性翻转对 |
|---|---|---|---|---|
| train | 12 | **10** | 2 | 4 |
| val | 8 | **0** | **8** | 6 |

- 训练集被**原成功态**主导（10/12），验证集**全是原失败态**
- 因此 100 步训练在 val 上其实是**分布外迁移**，不能当作泛化证据

## 6. 训练接线（100 步）

```
loss: 0.487 → 0.257（全程有限，无 NaN/Inf）
val pair_R2: 0.0008 → 0.154
val pair_acc: 0.75
checkpoint 重载: max|Δ| = 0.000e+00
supervision flag: baseline_continuation
```

分组（val，8 个 decisive 对）：

| 分组 | n | pair R² | pair acc |
|---|---|---|---|
| all | 8 | +0.154 | 0.750 |
| 原成功 Anchor | 0 | – | – |
| 原失败 Anchor | 8 | +0.154 | 0.750 |
| `|dC| > 0.5` | 4 | +0.160 | 0.750 |
| `|dC| ≤ 0.5` | 4 | +0.035 | 0.750 |

对照基线（同一批 decisive 对）：

| 预测器 | 准确率 |
|---|---|
| 恒预测零差 | 0.000（不可能是平局） |
| 多数符号（用 train 拟合，train dC 多数为 +1） | 0.625 |
| Head | 0.750 |

> val 只有 8 个 decisive 对，**1 个样本 = 12.5 个百分点**。0.75 vs 0.625 的差距等价于 1 个样本，**不构成泛化证据**。

## 7. 结论与下一步（严格按预设标准）

| 关口 | 结果 |
|---|---|
| 数据有效性 | **PASS**（10/10 有效、错误率 0、动作无越界） |
| 数据隔离 | **PASS**（episode 级不交叉） |
| 收益信号存在 | **PASS**（20/20 非零，10 对大幅值） |
| 训练接线 | **PASS**（loss/梯度有限、可存可载） |
| 初步泛化 | **无法判定**（8 对、且 val 全为失败态、train 全为成功态） |
| 闭环验证 | 未进行（按指令禁止） |

**当前状态**：Stage 1C 完成，工程链路可用，但样本量与划分偏差都不足以支撑任何泛化或成功率结论。

**建议的唯一一次有条件补采**（尚未执行，等待批准）：
1. 先只用原始基线跑训练源数据，筛出失败窗口（便宜）；
2. 仅对这些失败 Anchor 做昂贵反事实分支；
3. 保留少量成功 Anchor 作风险对照；
4. 固定 ε=0.3，不扫参，不触碰官方 50 任务集；
5. 目标：train/val 都同时包含成功态与失败态，每 split ≥ 20 对。

**不能做的事**：不接 Planner、不跑 50 任务、不扩大训练、不改 RAGC 架构。
